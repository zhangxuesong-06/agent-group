# AI 集群 · 多 Agent 协同平台

一个**能真正跑起来**的多 Agent 集群最小实现，外加一份面向生产的架构设计。

- 设计文档：[`docs/架构设计.md`](docs/架构设计.md)
- 远程访问与部署评估：[`docs/远程访问与部署.md`](docs/远程访问与部署.md)
- 可运行 MVP：[`mvp/`](mvp/)
- 默认 **mock 模式**，不需要任何 API Key 就能完整体验「规划 → 调度 → 工具调用 → 汇总」
- 配置 OpenAI 兼容接口后自动切换真实模型，代码不用改
- **控制面强制登录**：每台手机/电脑认证一次后保持会话，可单独撤销；worker 每设备独立 token

---

## 它解决了什么

不是「同时开几个聊天窗口」，而是：

1. **规划**：把目标拆成带依赖的任务 DAG
2. **调度**：按能力标签把任务分给不同 Agent，并控制并发
3. **执行**：每个 Agent 有独立的 system prompt、工具白名单和步数上限
4. **协同**：下游只拿上游的**摘要**，避免上下文爆炸
5. **兜底**：预算熔断、超时、死锁检测、取消、事件回放

## 快速开始

要求 Python 3.10+（已在 3.14 上验证）。

```powershell
# 方式一：双击 start.cmd，或
.\start.cmd

# 方式二：手动
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r mvp\requirements.txt
.\.venv\Scripts\python.exe mvp\run.py
```

启动后终端会同时打印本机和局域网地址：

```text
本机访问   http://127.0.0.1:8000
局域网访问 http://192.168.1.23:8000
```

手机、平板、另一台电脑连同一个 Wi-Fi，打开局域网地址即可。

> 认证是强制的。首次启动会自动生成 `ACCESS_TOKEN` 写入 `mvp/.env`，并在终端打印一次。每台设备第一次打开网页时输入它登录，之后保持登录；设置 → 访问 里可以查看和撤销已登录设备。
>
> 怀疑令牌泄露时：改掉 `mvp/.env` 里的 `ACCESS_TOKEN` 并重启（阻止新登录），再在设置 → 访问里撤销其他设备（清掉已有会话）。

也可以直接用命令行验证：

```powershell
# 另开一个终端，服务需已启动
.\.venv\Scripts\python.exe mvp\scripts\smoke.py
```

> `smoke.py` 会从环境变量或 `mvp/.env` 读取 `ACCESS_TOKEN`。

### 在同一台电脑上跑 worker（本地测试）

服务启动后，双击仓库根目录的 `start-worker.cmd`。首次会依次提示：

1. 服务器地址 —— 直接回车用 `http://127.0.0.1:8000`
2. 设备 token —— 网页「设置 → 设备 → ＋ 配对设备」生成
3. 设备名称 —— 直接回车用电脑名
4. 工作区绝对路径 —— 直接回车用 `mvp/data/workspace`，也可以填任意目录

配置保存在 `mvp/data/worker.json`，以后双击直接连接。要重配就运行：

```powershell
.\start-worker.cmd --reset
```

worker 断开后会自动重连；按 `Ctrl+C` 停止。

### 在网页里配置模型（推荐）

左下角点击「⚙ 设置 → 模型列表」：

1. 点 **「＋ 新增模型」** 可以继续添加，不会覆盖已保存的模型
2. 从预设里选一个：OpenAI、OpenAI Responses、OpenCode Go、DeepSeek、Moonshot Kimi、智谱 GLM、通义千问、SiliconFlow、Groq、Google Gemini、OpenRouter、Anthropic Claude、Ollama
3. 或选「自定义供应商」，填任意兼容接口
4. 选择 **API 类型**：
   - `OpenAI Chat Completions` → `POST /chat/completions`（最常用）
   - `OpenAI Responses` → `POST /responses`（适配只支持新版 Responses 的模型）
   - `Anthropic Messages` → `POST /messages`
5. 选择 **认证方式**：`Authorization: Bearer`、`x-api-key`、`api-key` 或不发送
6. 填写 Base URL、模型名、API Key
7. 点 **「获取模型」** 可从供应商的 `/models` 接口拉取可选模型；也可以直接手填
8. 点 **「测试连接」**，成功后「保存」
9. 连不上时点 **「诊断」**：会依次检查 DNS、TCP、HTTP、模型列表和代理环境

同一个供应商的不同模型，保存成多条供应商记录即可（Base URL、Key 相同，模型名不同）。

OpenCode Go 默认模型是 `deepseek-v4.1-flash`，也可以填写 `gpt-6-luna`、`claude-haiku-5-5`、`kimi-k3` 等 Go 支持的模型 ID。

**无需重启**，下一次运行立即使用新供应商。编辑时 API Key 留空表示保留已保存的值。

Base URL 会自动清理常见误填：如果你粘贴了 `https://host/v1/chat/completions` 或 `.../responses`，保存时会自动还原成 `https://host/v1`。

如果浏览器能访问供应商、但服务端报「LLM 请求失败」，通常是 Python 没有走系统代理。展开「高级：请求头 / 代理」填代理地址（如 `http://127.0.0.1:7890`），或在启动前设置 `HTTPS_PROXY` 环境变量。

API Key 保存在本机服务器的 SQLite 数据库中（明文，请注意磁盘权限），接口只返回 `****1234` 这样的掩码，不会把完整 Key 回传到浏览器。

#### 自定义供应商连不上时

| 现象 | 优先检查 |
| --- | --- |
| 401 / 403 | API Key、认证方式（Bearer / x-api-key / api-key） |
| 404 | Base URL 是否多了 `/chat/completions`；是否少了 `/v1` |
| 400 | 模型名是否存在；API 类型是否选对（Chat / Responses / Anthropic） |
| 422 | 该模型不接受这些参数，换模型或换 API 类型 |
| 429 | 限流或余额不足 |
| 524 | 上游/Cloudflare 网关超时：开启流式输出、降低思考强度、换更快模型 |
| 连接失败 | 服务器网络、代理、TLS 证书、内网地址 |
| 浏览器能访问但服务不能 | Python 不走系统代理，需在高级里填代理 URL（如 `http://127.0.0.1:7890`） |
| 需要额外请求头 | 展开「高级：请求头 / 代理」，填 JSON，例如 `{"X-Title":"ai-cluster"}` |

如果服务跑在 Docker 里，供应商地址是本机服务（如 Ollama），要用
`http://host.docker.internal:11434/v1`，不能用 `127.0.0.1`（容器里的 127.0.0.1 是容器自己）。

Azure OpenAI 可用自定义供应商：Base URL 填
`https://<resource>.openai.azure.com/openai/deployments/<deployment>?api-version=...`，
认证方式选 `api-key`，API 类型选 `OpenAI Chat Completions`。

#### 多模型路由与能力评分

可以同时启用多个模型：

1. 在「设置 → 模型列表」里添加供应商
2. 点击已保存的模型进入单独设置界面；点「＋ 模型」可以给同一供应商继续添加模型，连接配置和 Key 会自动沿用
3. 在「设置 → 模型路由评分」里按供应商分组管理模型
4. 每个模型单独勾选「参与路由」，并设置九个维度评分（0–10）：
   - 通用能力：调研、分析、写作、审校、通用
   - 工程能力：前端、后端、运维、通用编码
5. 选一个「默认」模型作为规划器
6. 如果不确定怎么打分，选择一个「评测评分模型」，点模型旁的「实测评分」：
   - 会向目标模型发送 9 个测试题（调研/分析/写作/审校/前端/后端/运维/编码/通用）
   - 评分模型根据目标模型的真实回答，按统一标准给 0–10 分
   - 默认从 5 分开始，只有明确满足标准才给 7 分以上
   - 结果包含分数、理由和缺失项，可手动调整后保存
   - 建议选一个不同的模型作为评分器，避免自评偏高
7. 调度时按任务 capability 选择该领域分数最高的模型，并扣减当前负载
8. 任务卡片会显示「供应商 · 模型」，方便确认是谁执行的

任务卡片会显示实际使用的模型。某个模型超时或临时不可用时，会自动尝试下一个分数最高的模型。

#### 思考强度与超时

供应商表单里可以设置：

- **思考强度**：自动 / 低 / 中 / 高
  - OpenAI Chat：发送 `reasoning_effort`
  - OpenAI Responses：发送 `reasoning: {"effort": "..."}`
  - 自动表示不发送，兼容不支持该参数的模型
- **单次请求超时**：0 表示使用全局 `LLM_TIMEOUT`（默认 300 秒）
- **流式输出**：默认开启。遇到 Cloudflare `524` 或网关超时时保持开启，模型输出会边生成边返回，避免长时间没有响应字节

如果「测试连接」成功但完整任务超时，通常是规划/工具调用上下文更长导致。把该供应商超时调到 300–600 秒，或再启用一个模型作为自动兜底。遇到 `524` 优先开启流式输出并降低思考强度。

### 界面布局

- **左侧**：新建任务、集群选择、可收起的任务列表，设置固定在左下角
- **中间**：对话式任务流，用户消息靠右、AI 回复靠左；顶部显示任务标题、状态、集群和操作按钮
- **底部**：常驻输入框，`Enter` 发送、`Shift+Enter` 换行；最大步数/预算/超时收在「参数」里
- 执行过程直接嵌在 AI 对话框里，作为可折叠的「思考过程」：规划器、每个 Agent 的当前步骤和 token 流都在这里实时更新
- 任务列表和事件流也收在「思考过程」内部
- 任务列表扁平显示，带状态、完成进度、集群名和时间
- 命令审批弹窗出现时会播放提示音、闪烁页面标题并弹网页 toast，避免错过
- 查看某次运行时，底部输入框用于**继续和对话模型交流**；要开新任务请点左上角「＋ 新建任务」

### 消息操作

鼠标移到对话框上时，底部会浮出图标按钮（带 tooltip）：

- **用户消息**：编辑、重新回答、引用、复制
- **AI 消息**：复制、选择文本、创建分支、删除
- **编辑**：直接在气泡内修改文本，保存后写回数据库；运行中的消息不允许编辑
- **引用**：像 QQ 一样在输入框上方出现引用条，发送后引用内容以引用块显示在新消息里
- **创建分支**：复制直到这条消息为止的完整会话（目标、聊天、已生成结果），创建一个独立的新 Run；分支不会重新执行，之后可以继续对话
- **选择文本**：直接选中该消息内容，方便用系统快捷键继续处理
- **删除**：对普通对话消息只删除这一条；对主结果/目标消息则删除整次运行

### 流式输出与双向对话

- OpenAI Chat Completions、Responses API 的 SSE token 会实时推送到页面
- 支持 `reasoning_content` / `reasoning` / Responses 推理摘要事件，思考内容和最终答案分开显示
- 单模型直连时，最终答案直接逐字出现在「模型输出」区域
- 多 Agent 模式下，每个 Agent 当前步骤的输出逐字显示在「思考过程」，汇总 Agent 的输出逐字写入「模型输出」
- 流式 token 只走实时通道，不写入数据库；刷新历史运行不会重放成千上万条增量事件
- 对话模型的回复也走独立的流式通道：可以一边接收回复一边继续发送下一条消息

### 专家团与主理人（每一轮都会重新调度）

每个 Run 有一个直接面对用户的**主理人模型**（多 Agent 集群用规划器模型，单模型模式用该模型）。
参考 WorkBuddy 专家团的做法，每条用户消息都会经过主理人判断，而不是只做直连聊天：

- **reply**：普通问答、追问、基于已有结果回答，直接流式回复
- **team**：需要新的检索、分析、写作、实现或验证时，主理人创建新一轮专家任务，分派给对应 Agent
  - 新一轮任务和上一轮完全隔离，只把上一轮结果作为上下文
  - 任务列表和事件流显示**当前轮**，历史轮次保留在会话消息里
  - 本轮完成后，主理人再基于专家产出写最终答复；答复单独作为一条消息追加到会话
- **guide**：已有任务正在执行、用户要求调整方向时，把要求注入正在执行的 Agent
  - 在该 Agent 的下一个模型步骤开始前生效，事件流里会出现「收到引导」
  - 如果在它完成前没有新的步骤，这条引导不会补跑
- 如果团队正在执行时用户又提出新的工作，主理人会把新要求转成引导发给正在执行的成员，避免同一 Run 并发调度
- 如果用户只是说“谢谢”或追问，不会创建新任务
- 主理人优先通过工具调用 `expert_action` 做决定；不支持工具的供应商会回退到 JSON/`GUIDE` 文本解析
- 单模型模式同样按这条规则走：简单问题直接回答，明确需要工作时也会创建任务，只是所有任务都由同一个模型执行

主理人判断失败时会退化为普通直连回复；如果回复里出现 `GUIDE[...]` 行，也会按引导处理。

### 并行任务

仍然可以同时运行多个任务：

- 点左上角「＋ 新建任务」随时发起新 Run，旧任务不会停止
- 每个 Run 独立调度，默认每个 Run 最多 `MAX_CONCURRENCY` 个并行子任务
- 左侧不再有「运行中」合并栏，任务列表里会标记仍在运行的状态

### 任务管理

运行历史里可以：

- 查看每个 Run 的任务 DAG、实时事件流、最终交付
- **■ 停止运行**：按钮排在最前并红色强调，优先级最高
  - 规划阶段也能停止，不必等模型返回
  - 立即取消进行中的模型请求和工具调用；即使模型尚未响应，也会关闭连接、停止消耗 token
  - 点击后按钮变为「正在停止…」，状态进入 `cancelling`，随后落为 `cancelled`
- **继续未完成**：保留已完成任务，从失败/跳过的节点继续运行
- **重试此任务**：在失败或跳过的任务卡片上单独重试，已完成的依赖不会重跑
  - 点击后卡片立即变为 `pending` / `running`，不会停留在旧的失败状态
- **重跑**：用相同目标和预算新建一次运行
- **删除**：删除运行记录、事件和产物
- 下载运行产物（`artifacts` 区域）
- 左侧「任务」和内页的任务/事件流都可以收起，状态会记住

### 服务重启与断点恢复

- 每个 Agent 在完成一批工具调用后，会把消息、工具观察结果和下一步编号写入 `tasks.checkpoint`
- 服务启动时会扫描 `planning` / `running` 的运行，把 `running` / `ready` 任务重置为 `pending`，再从检查点继续
- 已完成的任务和工具步骤不会重跑；崩溃瞬间正在执行的工具可能重跑一次（at-least-once），因此写文件/命令类工具要能接受重复执行
- 正常停止服务时会保留运行状态，下次启动自动恢复，不会把可恢复的运行误标成 `cancelled`
- 启动日志会打印 `[recover] resumed ...`，事件流里也会出现「服务重启，已从检查点恢复」

### 集群预设与单模型模式

左侧边栏顶部可以选择本次任务使用的集群：

- **全部模型**：使用所有已启用模型
- **已保存的集群**：只在该集群包含的模型里路由，不会用到集群外的模型
- 集群预设保存在数据库里，可新建、编辑、删除、设为默认
- 每个集群可以指定一个**规划器模型**，负责拆解任务和最终汇总
- 同一个目标可以用不同集群分别运行，互不影响
- **只有一个可用模型时自动进入单模型模式**：
  - 不调用规划器，不拆 DAG
  - **不分配 Agent 角色、不加载工具**，直接一次模型调用
  - 只创建一个直接执行任务，模型直接回答
  - 相比多 Agent 路径大幅减少 token 消耗
  - 界面上的「集群模式」开关会被强制关闭并禁用
- 多模型集群也允许手动关闭「集群模式」，此时同样只使用规划器模型直接回答

在 **设置 → 集群预设** 里管理集群；在左侧选择后点「启动任务」即可。

### 模型列表的两种视图

**设置 → 模型列表** 支持两种显示方式，选择会保存在浏览器里：

- **按供应商**：按连接分组，适合管理同一供应商下的多个模型
- **按模型**：平铺所有模型，按模型名排序，并显示所属供应商，适合快速找模型

两种视图都保留设置、档案、测试、删除和「＋ 模型」操作。

### 设置弹窗的返回层级

点击弹窗外或按 `Esc` 会逐级返回，而不是直接回到主页面：

1. MCP 编辑表单 → MCP 列表
2. 集群编辑表单 → 集群列表
3. 模型档案 → 设置页
4. 模型编辑表单 → 模型列表
5. 路由评分 / 集群预设 / 工作区 / MCP → 模型列表
6. 模型列表 → 关闭设置

所有确认框都在网页内完成，不使用浏览器原生 `alert` / `confirm` / `prompt`。

### 模型实测评分

每次「实测评分」都会持久化到数据库，模型列表/路由页会显示最近一次实测平均分。

- **实测评分**：只测单个模型，完成后自动填入该模型的路由表单
- **一键实测全部**：按顺序评测所有「参与路由」的模型，逐个把分数填回表单；运行中按钮变为「停止实测」，可随时中止
- 每道题都带**硬性检查点**：评分模型逐项核对，任一检查点失败总分不超过 6；全部通过后再按准确性、简洁度和额外洞察给 7–10 分
- 测试题覆盖 9 个维度，都是带明确约束的实操题（例如吞吐计算、区间合并、幂等队列 API、K8s 故障排查），不是泛泛的概念问答

点模型旁的「档案」可以查看：

- 最近一次实测的 9 个维度分数
- 每个维度的评分理由、硬性检查点通过数、缺失项
- 平均耗时、评测 token、估算成本
- 「应用到路由评分」按钮，把档案分数填回路由表单

### Web Search

调研 Agent 现在有 `web_search` 工具，会按顺序尝试可用提供方：

- 配置 `TAVILY_API_KEY` → Tavily
- 或 `BRAVE_API_KEY` → Brave Search
- 或 `SEARXNG_URL=https://your-searxng` → SearXNG
- 没有 Key 时使用 Bing HTML 搜索
- 最后回退 DuckDuckGo HTML

配置了某个提供方但请求失败时，会自动继续尝试下一个，而不是直接报错。全部失败时会返回每一步的错误原因。

> 当前网络环境下 DuckDuckGo、Brave 网页版和 Google 可能被阻断；Bing 通常可用。推荐至少配置 Tavily 或自建 SearXNG，调研质量和速度会明显好于 HTML 搜索。

### 本地工作区与真实工具

Agent 不再只是“给建议”，现在可以直接在你的电脑上工作。所有本地操作默认限制在一个工作区目录内：

- 默认工作区：`mvp/data/workspace`
- 启动后可以在 **设置 → 工作区** 里直接修改，保存立即生效，不需要重启
- 环境变量 `WORKSPACE_DIR` 只作为首次启动的默认值
- 设置页顶部会显示当前工作区路径、命令执行和审批状态

可用工具：

| 工具 | 作用 |
| --- | --- |
| `list_files` | 列出工作区内的目录和文件（限制深度与数量） |
| `read_file` | 读取工作区内的文本文件 |
| `write_file` | 创建或覆盖文件，自动建父目录 |
| `edit_file` | 精确替换文件片段，适合做最小改动 |
| `run_command` | 在工作区执行本地命令，返回 stdout/stderr 和退出码 |

安全边界：

- `list_files` / `read_file` / `write_file` / `edit_file` 会校验路径，禁止 `..` 或绝对路径逃出工作区
- 单文件读取上限 200KB，写入上限 1MB，命令输出上限 12KB
- 命令执行默认 60 秒超时；停止运行会同时终止正在执行的命令
- 命令使用启动服务的系统用户权限运行，**不是强沙箱**；不要用它跑来源不明的代码
- 不想让 Agent 执行命令时，在「设置 → 工作区」关闭「允许执行本地命令」

### 命令审批

默认开启 **命令审批模式**（`COMMAND_APPROVAL=1`）：

1. Agent 调用 `run_command` 时先暂停，不会直接执行
2. 网页弹出「命令待审批」，显示命令内容和所属运行/任务
3. 点「批准执行」才真正运行；点「拒绝」则把错误返回给 Agent，让它调整方案
4. 点「本次运行都允许」后，该 Run 后续的 `run_command` 不再逐条询问
5. 超过审批超时（默认 300 秒，可在设置里改）自动拒绝
6. 停止运行会同时取消该运行所有待审批命令

关闭审批后，命令会在工作区内自动执行。审批覆盖本地和远程设备的 `run_command`；MCP 工具调用不受这一层审批控制。

### MCP 工具接入

在 **设置 → MCP 工具** 里可以添加任意 MCP（Model Context Protocol）服务器：

- 支持 **stdio**（本地进程，如 `npx @modelcontextprotocol/server-filesystem`）
- 支持 **SSE** 和 **Streamable HTTP**
- 内置常用预设：文件系统、网页抓取、Git、SQLite、时间、记忆图谱、分步思考、Context7、Playwright、Brave 搜索、GitHub、Everything 测试服务器
- 预设会按当前工作区替换 `{workspace}` 占位符，填好后仍可手动修改
- 保存后自动连接，连接成功会把该服务器的工具注册给 Agent
- 支持测试连接、连接/断开、编辑、删除；配置持久化在数据库里
- 环境变量和请求头在接口里只返回键名，不返回值；编辑时留空保持原值

Agent 看到的是 `mcp__<服务器ID>__<工具名>` 形式的工具，调用与内置工具一致。MCP 服务器和本地命令一样以服务进程权限运行，请只添加可信服务器。

stdio 服务器的命令必须已经安装在运行服务的机器上（例如 `npx` 需要 Node.js）。如果使用 Docker，记得把对应运行时装进镜像。

> **安全提醒**：工作区、命令执行、审批和 MCP 配置都通过 API 暴露。控制面现在强制登录：每台设备首次访问需要 `ACCESS_TOKEN`，之后使用会话，可在设置 → 访问里撤销；worker 使用每设备独立 token。文件传输仍建议走 Tailscale 或 HTTPS，不要在公网明文暴露 `8000`。

常用示例：

```text
名称：filesystem
传输：stdio
命令：npx
参数：
  -y
  @modelcontextprotocol/server-filesystem
  C:\Users\you\projects\demo
```

最快的方式是点「＋ 添加 MCP 服务器」后，先在 **从预设开始** 里选一个预设；它会自动填好命令、参数、URL 和环境变量键名。`{workspace}` 会替换成当前工作区路径，保存前可以继续改。

```text
名称：my-http-mcp
传输：streamable_http
URL：http://127.0.0.1:3001/mcp
```

### 用环境变量配置（可选）

也可以不用网页，把 `mvp/.env.example` 复制为 `mvp/.env`：

```ini
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
```

环境变量只在数据库里还没有任何供应商时导入；之后以网页里启用的供应商为准。

任何 OpenAI Chat Completions / OpenAI Responses / Anthropic Messages 兼容接口都可以（DeepSeek、Qwen、vLLM、Ollama 的 `/v1` 等）。

### 从其他设备 / 云端访问

- 局域网：直接用启动时打印的 `http://局域网IP:8000`
- 跨网络个人使用：推荐 Tailscale，无需公网 IP 和端口映射（见 [`docs/tailscale.md`](docs/tailscale.md)）
- 公网 HTTPS：Cloudflare Tunnel，务必同时设置 `ACCESS_TOKEN`
- 7×24 云端：`docker compose --env-file deploy/.env.cloud -f docker-compose.cloud.yml up -d --build`（Caddy 自动 HTTPS）
- **云端 + 远程工作区**：设置 → 设备里配对 token，在每台电脑上运行 `mvp.worker.agent`；设备主动外连服务器。网页里选择在线设备和工作区后，文件/命令工具会在该设备执行
  - 可以点「浏览…」逐级查看设备目录，选子目录作为 workspace
  - 每台设备的选择会单独记住，下次自动恢复
  - 服务器只暴露 80/443
  - 每台设备一个独立 token，按 workspace 根目录授权
  - 设备离线时不能创建新任务；运行中掉线会报工具错误，重新上线后可继续

完整步骤、配对命令、安全清单和限制见
[`docs/cloud-deployment.md`](docs/cloud-deployment.md)。
只想自己用、不想开公网端口时，见 [`docs/tailscale.md`](docs/tailscale.md)：
手机当控制器，通过 Tailscale 打开网页；执行仍在已配对的电脑 worker 上。
旧的局域网/隧道方案见 [`docs/远程访问与部署.md`](docs/远程访问与部署.md)。

## 一次运行发生了什么

```text
POST /api/runs
  → 解析集群快照（cluster_id / cluster_mode）
  → 创建 Run（planning）并保存模型快照
  → 单模型模式：跳过 Planner 和 Agent 角色，直接一次模型调用回答
  → 多模型模式：Planner 产出 4~5 个任务（mock 用规则，真实模型用 JSON 约束）
  → 校验 DAG，落库，发布 run.planned
  → Scheduler 找「依赖已满足」的任务
  → 按 capability 选 Agent（能力匹配 + 最少负载）
  → 只在当前集群的模型里路由，集群外的模型不会参与
  → Worker 执行 Agent Loop，每步发 agent.step 事件
  → 工具调用统一走 Tool Registry，带超时与错误隔离
  → 全部完成 → 汇总 → run.completed
```

默认 Agent 团队：

| Agent | 能力 | 工具 |
| --- | --- | --- |
| 调研员 researcher | research | 网页检索、抓网页、读本地文件、时间 |
| 分析师 analyst | analysis | 检索、计算、读本地文件 |
| 撰写员 writer | writing | 检索、读取/写入工作区、保存产物 |
| 审校员 reviewer | review | 检索、读文件、执行测试命令 |
| 工程师 engineer | code / frontend / backend / devops | 读写/编辑文件、执行命令、计算、检索 |
| 通用执行者 generalist | general | 检索、计算、时间、读写/编辑文件、执行命令 |

## 已实现的工程能力

- 事件溯源：所有状态变更都写入 `events` 表，UI 与审计只消费事件
- 预算熔断：`max_steps` / `max_tokens` / `max_usd` / `deadline`
- 默认 Token 预算 2,000,000（推理模型很容易消耗几万 token / 步，可在提交任务时调整）
- 默认运行超时 1 小时（6 个并行调研任务建议不少于 30 分钟）
- 并发控制：`MAX_CONCURRENCY`，按能力负载选 Agent
- 死锁检测：有 pending 但无可运行任务时直接失败，不会挂死
- 工具安全：`calc` 只允许数字与四则运算；`fetch_url` 拒绝内网地址；文件工具禁止越出工作区；命令执行有超时、输出上限和危险命令拦截
- 工作区：网页内修改绝对路径，立即生效；支持命令开关
- 命令审批：run_command 执行前在网页里批准或拒绝，超时自动拒绝
- MCP：stdio / SSE / Streamable HTTP，工具自动注册给 Agent，支持测试与热连接
- 可回放：SSE 支持 `after=<seq>` 断线重连
- 远程访问：监听 `0.0.0.0`、可选的 Bearer Token、SSE 失败自动降级轮询
- 模型列表：网页内增删改查、按供应商/按模型双视图、14 个预设 + 自定义、3 种 API 类型、模型列表拉取、连接诊断、Key 掩码、热切换
- 多模型路由：领域能力评分 + 负载均衡 + 默认模型 + 超时/故障自动切换
- 集群预设：保存模型组合，不同任务选择不同集群，运行保存不可变快照
- 单模型模式：集群只有一个可用模型时跳过规划器，不分配 Agent 角色、不加载工具，单次模型调用直接回答
- 界面：对话式布局、用户消息靠右、执行过程内嵌为「思考过程」、图标式消息悬停操作、左侧固定设置入口、模型列表双视图
- 消息操作：气泡内编辑、QQ 式引用、会话分支、引用块渲染、删除单条消息
- 双向对话：运行中/结束后都能继续和对话模型交流，回复逐 token 流式输出
- 专家团：主理人对每条消息判断 reply / team / guide，后续消息也会重新调度新一轮专家任务
- 插话/引导：主理人可通过结构化引导在执行模型的下一步注入指令
- 并行任务：多个 Run 仍可同时执行，通过「新建任务」发起
- 审批提醒：命令审批弹窗出现时播放提示音、闪烁标题并显示网页 toast
- 实测评分：9 个维度真实测试、硬性检查点、评分模型评估、结果持久化、模型档案与一键应用
- 一键实测：按顺序评测所有参与路由的模型，可中途停止，分数自动填表
- 本地工具：工作区文件增删改查 + 命令执行，路径越界与危险命令拦截
- 断点继续：保留已完成任务，从失败节点继续；支持单任务重试
- Web Search：Tavily / Brave / SearXNG / Bing / DuckDuckGo 自动回退
- 思考强度与超时：按供应商设置 reasoning effort、单次请求超时和流式输出
- 流式输出：Chat Completions / Responses 均支持 SSE token 与推理增量；增量事件实时推送但不落库，工具调用增量聚合，缓解 524
- 步数保护：达到工具调用上限后自动要求模型不带工具收尾，不会直接判失败
- 任务管理：取消、重跑、删除运行，产物列表与下载
- 零依赖启动：SQLite + 进程内总线，不需要 Redis/Postgres

**刻意没做**（留给 Phase 2，接口已预留）：

- 用户体系、RBAC 与多租户
- 跨进程 / 分布式 Worker
- MCP 资源 / 提示词 / OAuth 与沙箱容器
- 向量记忆与对象存储
- 多副本 Orchestrator 选主

这些在架构文档里都有对应章节。
