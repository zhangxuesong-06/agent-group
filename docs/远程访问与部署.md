# 远程访问与云端部署 · 可行性评估

> 结论先行：
> **个人 / 小团队在其他设备上远程使用：可行，现在就能用。**
> **把它当成公网多用户 SaaS：当前架构还不够，需要先做 Phase 2 改造。**

---

## 1. 为什么之前换个设备打不开

三个原因，按出现概率排序：

1. **服务只监听 `127.0.0.1`**：其他设备访问 `127.0.0.1:8000` 时，访问的是那台设备自己，不是你的电脑。
2. **用了 `localhost`**：部分浏览器优先解析到 IPv6 `::1`，而旧配置只绑定了 IPv4 `127.0.0.1`。
3. **直接双击了 `index.html`**：`file://` 页面没有后端，所有 `fetch` 都会失败。

现在默认改为：

- 监听 `0.0.0.0`，局域网可直接访问
- 启动时打印本机 / 局域网访问地址
- 页面连不上时显示明确提示，而不是白屏
- 支持 `ACCESS_TOKEN` 访问令牌
- SSE 不可用时自动降级为轮询（兼容代理 / 老浏览器）
- 移动端布局适配

启动：

```powershell
# Windows 双击，或：
.\start.cmd

# 或手动
.\.venv\Scripts\python.exe mvp\run.py
```

也可以用 `OPEN_BROWSER=1` 自动打开浏览器。

## 2. 能力边界：哪些能远程，哪些不能

| 能力 | 远程可用性 | 说明 |
| --- | --- | --- |
| 提交任务 / 查看进度 | ✅ | 浏览器只做控制面，SSE 实时推送 |
| 查看最终结果 / 下载产物 | ✅ | 已提供 `/api/runs/{id}/artifacts` |
| 调用模型 | ✅ | 模型请求发生在**服务器**，不在手机/平板上 |
| 执行工具（抓网页、计算） | ✅ | 同样在服务器侧执行 |
| 多设备同时使用 | ⚠️ | 单进程可支撑几个人，但没有租户隔离和配额 |
| 多人权限管理 | ❌ | 只有一个共享令牌，没有用户体系 |
| 多实例水平扩展 | ❌ | 进程内事件总线 + SQLite，只适合单实例 |
| 服务重启后续跑 | ❌ | 进行中的 Run 不会自动恢复 |
| 大规模并发任务 | ⚠️ | 单进程 asyncio，建议并发 ≤ 10 |

**关键点：计算发生在服务器，客户端只负责发指令和看结果。** 所以用旧手机、平板、低配笔记本远程使用完全没问题；真正的瓶颈在服务器和模型 API。

## 3. 五种接入方式对比

| 方式 | 适用场景 | 安全性 | 成本 | 难度 |
| --- | --- | --- | --- | --- |
| 局域网直连 | 家里 / 办公室同一 Wi-Fi | 中（需令牌 + 防火墙） | 0 | ⭐ |
| Tailscale / ZeroTier | 个人跨网络远程 | 高（WireGuard 加密） | 免费 | ⭐⭐ |
| Cloudflare Tunnel | 需要公网 HTTPS、无公网 IP | 高（TLS + 可加 Access） | 免费起步 | ⭐⭐ |
| VPS + Docker + Caddy | 稳定云端服务 | 高（可控） | $5–20/月 | ⭐⭐⭐ |
| SSH 反向隧道 | 临时演示 / 内网穿透 | 高 | 取决于服务器 | ⭐⭐ |

> **不建议**把 8000 端口直接映射到公网。没有 TLS、没有登录体系、没有限流，等于把模型额度和工具执行权限交给全互联网。

## 4. 方式 A：局域网（最快）

### 4.1 配置

`mvp/.env`：

```ini
HOST=0.0.0.0
PORT=8000
ACCESS_TOKEN=换成一个足够长的随机字符串
```

生成随机令牌：

```powershell
# PowerShell
-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 40 | % {[char]$_})
```

```bash
# Linux / macOS
openssl rand -hex 24
```

### 4.2 放行防火墙（Windows，仅专用网络）

```powershell
New-NetFirewallRule -DisplayName "AI Cluster 8000" `
  -Direction Inbound -Protocol TCP -LocalPort 8000 `
  -Action Allow -Profile Private
```

### 4.3 访问

启动后终端会打印：

```text
AI Cluster 已启动
├─ 本机访问   http://127.0.0.1:8000
├─ 局域网访问 http://192.168.1.23:8000
```

手机连同一个 Wi-Fi，打开局域网地址，输入 `ACCESS_TOKEN` 即可。

令牌会保存在当前浏览器的 localStorage，并写入同源 cookie。实时事件流（SSE）通过 cookie 鉴权，**不会把令牌放在 URL 里**，避免出现在访问日志中。

### 4.4 排查

- 手机和电脑必须在同一网段，访客 Wi-Fi 常开启「AP 隔离」
- 公司网络可能禁止设备互访
- Windows 首次启动会弹防火墙提示，要选「专用网络」
- 路由器重启后 IP 可能变化，建议在路由器里给电脑固定 IP

## 5. 方式 B：Tailscale（个人远程首选）

适合「人在外面，想连家里电脑上的集群」，不需要公网 IP、不需要端口映射。

```text
电脑 A（跑集群）  ── Tailscale 虚拟网络 ──  手机 / 笔记本
```

步骤：

1. 电脑和手机都安装 Tailscale，登录同一账号
2. 电脑上执行 `tailscale ip -4`，得到 `100.x.y.z`
3. 手机访问 `http://100.x.y.z:8000`
4. `ACCESS_TOKEN` 照常填写

优点：

- 全程 WireGuard 加密，不暴露公网端口
- NAT 穿透成功时延迟很低
- 免费额度对个人足够

注意：电脑休眠后不可访问；需要在电源设置里允许网络唤醒，或改用常开的云服务器。

## 6. 方式 C：Cloudflare Tunnel（要公网 HTTPS）

适合「没有公网 IP，但想让外网稳定访问」。

临时试用：

```bash
cloudflared tunnel --url http://127.0.0.1:8000
```

它会返回一个 `https://xxx.trycloudflare.com` 地址。**必须同时设置 `ACCESS_TOKEN`**，否则等于公开服务。

长期使用建议创建命名隧道并绑定自己的域名：

```bash
cloudflared tunnel login
cloudflared tunnel create ai-cluster
cloudflared tunnel route dns ai-cluster cluster.example.com
cloudflared tunnel run --url http://127.0.0.1:8000 ai-cluster
```

SSE 注意事项：

- 本项目已返回 `X-Accel-Buffering: no` 和 `Cache-Control: no-transform`
- Cloudflare 一般可正常透传 SSE；若被缓冲，前端会自动降级为 1.5 秒轮询
- 不建议对 SSE 开启「缓存一切」类规则

## 7. 方式 D：VPS + Docker + Caddy（推荐云端方案）

### 7.1 服务器规格

| 规模 | 建议 |
| --- | --- |
| 个人 / 演示 | 2 vCPU / 2 GB RAM / 20 GB SSD |
| 小团队（3–5 人） | 4 vCPU / 4 GB RAM / 50 GB SSD |
| 高并发 / 多 Worker | 8 vCPU+，拆分独立 Worker 与 Postgres |

模型推理如果走 API，服务器本身不需要 GPU；只有自托管模型才需要 GPU 机器。

### 7.2 部署

```bash
git clone <your-repo> ai-cluster && cd ai-cluster
cp mvp/.env.example mvp/.env
# 编辑 mvp/.env：填 ACCESS_TOKEN、LLM_BASE_URL、LLM_API_KEY
docker compose up -d --build
docker compose logs -f
```

数据持久化在 Docker volume `cluster-data`，容器重建不丢 Run 历史。

### 7.3 加 TLS（Caddy）

`Caddyfile`：

```caddyfile
cluster.example.com {
    reverse_proxy 127.0.0.1:8000 {
        flush_interval -1
    }
}
```

`flush_interval -1` 对 SSE 很重要，否则实时日志会被缓冲。

### 7.4 最小安全清单

- [ ] `ACCESS_TOKEN` 至少 32 位随机字符
- [ ] 只开放 80/443，8000 不对外
- [ ] 云厂商安全组只放行必要端口
- [ ] 模型 API Key 只保存在服务器（`.env` 或 SQLite），不进浏览器；网页只显示掩码
- [ ] SQLite 中的供应商 Key 是明文，注意磁盘权限、备份加密和整机访问控制
- [ ] 定期备份 `cluster-data` volume
- [ ] 给容器设置资源限制（CPU / 内存）
- [ ] 日志里不要打印密钥

## 8. 方式 E：SSH 反向隧道（临时演示）

把本地 8000 映射到一台有公网 IP 的服务器：

```bash
ssh -N -R 0.0.0.0:8000:127.0.0.1:8000 user@your-vps
```

然后在 VPS 上通过 `http://vps-ip:8000` 访问。记得：

- VPS 防火墙放行端口
- 仍然设置 `ACCESS_TOKEN`
- 连接断开后隧道失效，适合临时演示，不适合长期服务

## 9. 云端多用户：现在缺什么

如果目标是「团队共用一个集群平台」，当前 MVP 需要补：

| 缺口 | 现状 | 改造方向 |
| --- | --- | --- |
| 用户体系 | 单一共享令牌 | OIDC / 邮箱登录 + RBAC |
| 多租户 | 无 `tenant_id` | 所有表加租户字段 + 行级隔离 |
| 配额 | 只有单 Run 预算 | 租户级日/月配额 + 限流 |
| 水平扩展 | 进程内总线、单实例 | Redis Streams / NATS + 独立 Worker |
| 持久化 | SQLite | PostgreSQL + 对象存储 |
| 断点恢复 | 重启丢进行中任务 | 任务状态机持久化 + 租约/心跳 |
| 审计 | 只有事件日志 | 操作审计、密钥轮换、导出 |
| 隔离 | 工具在宿主进程 | 容器 / gVisor 沙箱执行 |
| 可观测 | 日志 + 页面 | OpenTelemetry + Prometheus + 告警 |

按架构文档的 Phase 2 推进即可，接口已经预留：

- `bus.py` 的 `publish/subscribe` 可直接换成 Redis Streams
- `orchestrator._execute` 可拆成独立 Worker 消费队列
- `store.py` 可替换为 Postgres 实现
- 工具注册表可迁移到 MCP Gateway

**在这些完成之前，建议把服务定位为「个人 / 小团队工具」，不要直接对外提供多租户服务。**

## 10. 性能与成本预估

| 项目 | 估算 |
| --- | --- |
| 控制面延迟 | 局域网 < 10ms，公网 50–200ms |
| SSE 事件量 | 单任务约 10–30 条，流量可忽略 |
| 单 Run 典型 token | 2k–20k（取决于任务数） |
| 单 Run 成本（gpt-4o-mini 级） | $0.001–$0.02 |
| 单实例并发 | 4–10 个 Run（可调 `MAX_CONCURRENCY`） |
| 服务器月成本 | 轻量 VPS $5 起 |

真正的成本大头是模型调用，不是服务器。建议始终设置 `MAX_USD`、`MAX_TOKENS`、`DEADLINE_SEC`。

## 11. 推荐路径

1. **今天**：局域网 + `ACCESS_TOKEN`，手机先能用
2. **本周**：装 Tailscale，解决外网访问，不碰路由器
3. **需要固定域名**：Cloudflare Tunnel
4. **需要 7×24 稳定**：VPS + Docker Compose + Caddy
5. **要给团队用**：先做 Phase 2（登录、租户、Postgres、Redis、独立 Worker），再谈公网多用户
