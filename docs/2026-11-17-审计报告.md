最需要先知道的三件事：

1. **`ACCESS_TOKEN` 为空时，`Authorization: Bearer `（尾随空格）可直接通过鉴权**（SEC-01）。已用项目自带的 httptools 0.9.0 与 `hmac` 实测。当前 `run.py` 还在提示“未设置 ACCESS_TOKEN 时同一网络内任何人都能调用 API”，用户很可能主动清空 token。
2. **专家团对话与主调度器可以并发**（RUN-01），会触发“调度死锁”并把任务标成 skipped；轮次取消也取消不掉（RUN-02）。这两条会让“断点恢复/停止运行”这两个已宣称的能力在专家团模式下不可靠。
3. **桌面端空闲时后台轮询被门控成死循环**（UI-05）：页面打开时没有进行中的运行，之后手机发起新运行，桌面永远看不到，也永远不拉审批。这直接破坏 HANDOVER §0 的验收口径。

## P0

### SEC-01 空 `ACCESS_TOKEN` 可被空 Bearer 值绕过鉴权

- **状态**：✅ 已修复（2026-11-17）。`_token_ok` / `_bearer_ok` 拒绝空值与非 ASCII；`Settings` 对空/空白 token 重新生成。回归：`mvp/tests/test_auth.py::test_empty_server_token_never_authorizes`（修前 200，修后 401）。
- **证据**：✅ 实测。httptools 0.9.0 解析 `Authorization: Bearer ` 得到 `b'Bearer '`（保留尾随空格）；`hmac.compare_digest("", "") is True`。
- **位置**：`mvp/app/main.py:272-278`、`mvp/app/config.py:30-58`、`mvp/app/config.py:135-136`
- **触发条件**：
  1. `mvp/.env` 或容器环境里存在 `ACCESS_TOKEN=`（显式空值），或 `.env` 里只有注释含 `ACCESS_TOKEN`（见 SEC-02）。
  2. `__post_init__` 看到 `not self.access_token` 后调用 `_ensure_access_token`，后者读到 `ACCESS_TOKEN=` 这一行，`return ""`，最终 `settings.access_token == ""`。
  3. 客户端发送 `Authorization: Bearer `（Bearer 后一个空格）。
- **后果**：中间件 `header[7:].strip()` 得到空串，与空 token 比较为真，`request.state.auth={"kind":"token"}`，所有 `/api/*` 放行。攻击者不需要知道任何口令。
- **修法**：
  - `_ensure_access_token` 解析到空值时必须重新生成并落盘，不允许返回空串。
  - `__post_init__` 在最终仍为空时直接抛异常拒绝启动。
  - 中间件在比较前先 `if not supplied: 401`。
  - 比较改用 UTF-8 bytes（同时修掉 SEC-03）。

## P1

### SEC-02 `.env` 含 `ACCESS_TOKEN` 字样但无规范行时，静默使用不落盘、不打印的随机 token

- **状态**：✅ 已修复（2026-11-17）。`_read_env_token` 按 dotenv 语义解析：忽略注释行、剥离行内 `#` 注释、展开引号、支持 `export` / CRLF / BOM / GBK；`ACCESS_TOKEN= # 占位`、`ACCESS_TOKEN=#` 等占位值视为空并重新生成。回归：`mvp/tests/test_config_token.py`。
- **证据**：✅ 读码。
- **位置**：`mvp/app/config.py:36-41`
- **触发**：`.env` 里写 `#ACCESS_TOKEN=xxx`、`ACCESS_TOKEN: xxx`、`ACCESS_TOKEN = xxx`（带空格）等。`"ACCESS_TOKEN" in existing` 成立，循环无匹配，`return token`；这个分支既不写文件也不打印，重启后又换一个新随机值。
- **后果**：登录永久 401，日志没有任何提示，用户只能翻源码。
- **修法**：统一用 `python-dotenv` 的解析结果（`dotenv_values`），或按 `^\s*ACCESS_TOKEN\s*=\s*(\S+)\s*$` 逐行匹配；未解析到有效值时走“生成 + 写入 + 打印”路径。

### SEC-03 非 ASCII 令牌触发 `compare_digest` TypeError → 未认证 500，且不计登录失败次数

- **状态**：✅ 已修复（2026-11-17）。`_token_ok` 用 UTF-8 bytes 比较；非 ASCII 登录现在返回 401。回归：`mvp/tests/test_auth.py::test_non_ascii_login_is_401_not_500`。
- **证据**：✅ 实测 `hmac.compare_digest("中文", "token")` 抛 `TypeError: comparing strings with non-ASCII characters is not supported`。
- **位置**：`mvp/app/main.py:275`、`mvp/app/main.py:303`
- **触发**：`POST /api/auth/login {"token":"中文"}`，或请求头里放 `Bearer 中文`（HTTP 头按 latin-1 解码可出现非 ASCII）。
- **后果**：500；登录路径在计数之前就抛异常，所以可无限刷 500 和日志。
- **修法**：比较前统一 `supplied.encode("utf-8")` 与 `token.encode("utf-8")`；或在非 ASCII 时直接 401。

### SEC-04 `/docs`、`/redoc`、`/openapi.json` 不经过鉴权中间件

- **证据**：✅ 读码。`FastAPI(...)` 未关闭文档端点；中间件对非 `/api` 前缀直接放行。
- **位置**：`mvp/app/main.py:157`、`mvp/app/main.py:267`
- **后果**：未登录即可枚举全部 API、参数模型、WebSocket 与设备协议。
- **修法**：默认 `docs_url=None, redoc_url=None, openapi_url=None`；需要时用独立开关（如 `ENABLE_API_DOCS=1`）打开，且打开时也走鉴权。

### SEC-05 CORS `allow_headers=["*"]` 抵消 CSRF 自定义头（同站子域场景）

- **证据**：✅ 读码。默认 `CORS_ORIGINS=*`，`allow_methods/allow_headers` 全通配。
- **位置**：`mvp/app/main.py:158-163`、`mvp/app/main.py:283-285`
- **后果**：`SameSite=Strict` 拦不住同一注册域下的兄弟子域（如 `wiki.example.com` → `cluster.example.com`）。单机/局域网部署风险低，云端共享父域时成立。
- **修法**：不启用 `allow_credentials` 时，把 `allow_headers` 收窄到白名单并排除 `X-Requested-With`；或改用双提交 cookie / 校验 `Origin`。

### SEC-06 撤销/登出会话不会中断已建立的 SSE 与流式对话

- **证据**：✅ 读码。鉴权只在请求进入时做一次；`delete_session` 只删一行 DB 记录。
- **位置**：`mvp/app/main.py:1411-1416`、`mvp/app/main.py:1292-1303`
- **后果**：丢失的设备在“访问”页被撤销后，已经打开的 `/api/runs/{id}/events` 或 `POST /messages` 流仍持续输出，直到运行结束。
- **修法**：SSE/流生成器每个心跳周期复核会话是否仍存在，消失则关闭流；或给会话加 `revoked` 标志并由流读取。

### SEC-07 子进程继承全部环境变量，主令牌与供应商 Key 可被导出到模型上下文

- **证据**：✅ 读码。`create_subprocess_shell` 未传 `env=`。
- **位置**：`mvp/app/tools.py:583-588`、`mvp/worker/agent.py:220-225`
- **触发**：模型执行 `run_command {"command":"set"}`（Windows）或 `env`。
- **后果**：`ACCESS_TOKEN`、`LLM_API_KEY`、`TAVILY_API_KEY`、`BRAVE_API_KEY`、worker 的 `CLUSTER_WORKER_TOKEN` 全部进入工具结果 → SQLite → 发往第三方模型。设备端 shell 默认开启且没有审批，远程侧是自动发生的。
- **修法**：显式构造白名单 `env=`，剔除 `ACCESS_TOKEN`、`*_API_KEY`、`CLUSTER_WORKER_TOKEN`、代理变量；服务端与 worker 共用同一个 helper。

### SEC-08 `fetch_url` SSRF：只校验字面 IP，域名解析到内网一律放行；响应体无上限

- **证据**：✅ 读码。
- **位置**：`mvp/app/tools.py:337-357`
- **触发**：`http://localtest.me:8000/`、`http://10.0.0.5.nip.io/`、`http://router/`。主机名分支直接跳过私网检查。

### SEC-09 worker `fs.list` 沿符号链接/junction 越界枚举

- **证据**：✅ 读码。`path.is_dir()` 会跟随链接，链接目标被加入 BFS 队列。

### DATA-02 运行/任务/事件的 JSON 列解析无容错，坏一行导致整页 500

### DATA-03 SSE 回放上限 2000、忽略 `Last-Event-ID`、慢消费者静默丢事件

- **证据**：✅ 读码。
- **位置**：`mvp/app/store.py:836-841`、`mvp/app/main.py:1411-1436`、`mvp/app/bus.py:47-56`
- **后果**：
  - 事件数超过 2000 的运行，第 2001 条之后的历史永远不再回放。
  - 标准 EventSource 自动重连会从头重放（重复），而不是从断点续传。
  - 订阅队列满 1000 时静默丢最旧一条，可能是 `task.completed`；SSE 循环没有缺口检测，客户端无从察觉。
- **修法**：回放用 `while` 循环按批续拉直到取空；读取 `Last-Event-ID`；队列溢出时发 `event: gap` 让客户端重新拉 snapshot。

### DATA-04 删除设备后不关闭 worker 的 WebSocket，设备变僵尸

- **证据**：✅ 读码。`detach()` 只 `cancel_all()` 并从字典移除，不 `close()`。
- **位置**：`mvp/app/main.py:760-767`、`mvp/app/devices.py:138-148`
- **后果**：worker 侧永远显示已连接、永不重连；服务端对该设备的调用全部报“未连接”，直到 worker 进程重启。

### DATA-05 worker WebSocket 收到非 JSON / 非对象帧时抛未捕获异常

- **证据**：✅ 读码。`receive_json()` 的 `ValueError` 与 `message.get` 的 `AttributeError` 都不在 `except` 列表里。
- **位置**：`mvp/app/main.py:898`、`918`、`938`
- **后果**：任一 worker 版本 bug 或代理截断一帧，服务端刷 traceback、设备莫名掉线。
- **修法**：把 `(ValueError, AttributeError, TypeError)` 并入捕获；非 dict 消息直接忽略并回一条 error。

### RUN-01 专家团对话与主调度器可并发，触发伪“调度死锁”并丢任务

- **证据**：✅ 读码。`_drive` 不持有 `_round_locks`；`_drive` 在 `orchestrator.py:1185` 直接 `run.tasks = await self._plan(run)` 重绑列表。
- **位置**：`mvp/app/orchestrator.py:301-305`、`391-411`、`767-798`、`1169-1186`、`1519-1533`
- **触发**：运行还在 `planning`（规划 LLM 未返回、DB 里没有任务）时，用户在同一条对话里再发一句要求做事的话。`post_message` 不校验运行状态，`active_tasks` 为空，于是 `front_chat` 起新轮并启动 `_run_round`。
- **后果**：两个 `_schedule` 同时跑。轻则第二个调度器看到“自己的 running 为空 + pending 上游未完成”，写 `run.error="调度死锁"` 并把 pending 全标 skipped；重则 `_drive` 重绑 `run.tasks`，刚建的轮次任务从内存消失，DB 留下永远不执行的 pending，`_drive` 结束后 `_runs.pop` 又让 cancel 找不到运行，形成僵尸。
- **修法**：`front_chat` 在 `run.status in ("planning","cancelling")` 时明确拒绝；所有调度入口（`_drive` / `_run_round` / resume）共用同一把 run 级锁；`_drive` 用 `run.tasks[:] = ...` 而不是重绑。

### RUN-02 用户取消专家团轮次时，`_run_round` 不被取消，运行终态被改写成 failed

- **证据**：✅ 读码。`_run_round` 创建的 task 只进 `_bg`；`cancel()` 只取消 `_running_tasks` 与 `_run_tasks`。
- **位置**：`mvp/app/orchestrator.py:443-447`、`884-942`、`788-820`
- **后果**：轮调度器看到 `run.cancelled` 后 break，但 `_run_round` 继续把 `run.status` 置为 `failed`、发布 `run.status=failed`，从不发布 `run.cancelled`；若本轮已有 done 任务，还会照常调 LLM 做总结——取消之后继续花钱。
- **修法**：把轮任务登记进 `_run_tasks`（或 `_running_tasks`）以便 `cancel()` 取消；`_run_round` 在 `_schedule` 返回后先判 `run.cancelled`，发布 `run.cancelled` 并跳过总结。

### RUN-03 checkpoint 持引用 `messages`，可能在 tool_calls 未配对时落库，恢复后 400 必败

- **证据**：✅ 读码（引用与保存时机）。`_save_checkpoint` 直接存 `messages` 引用；`_execute` 的 `finally` 会把被后续 append 修改过的 checkpoint 落库，而 `next_step` 仍停在上一轮批次。
- **位置**：`mvp/app/orchestrator.py:2131-2147`、`1785`、`1908-1928`
- **后果**：服务优雅重启或预算异常发生在“assistant 带 tool_calls、工具结果尚未补齐”的窗口时，恢复后的消息序列缺 tool 消息，OpenAI/Anthropic 返回 400；`llm.py` 判定 400 不可重试，任务直接失败，下游全部 skipped。
- **修法**：保存时 `copy.deepcopy(messages)`；只在“每个 tool_call 都已有 tool 结果”的边界落 checkpoint；恢复时若发现不一致，丢弃尾部未配对的 assistant tool_calls。

### RUN-04 任务已 `done` 后被取消会翻回 `skipped`，丢掉已完成结果

- **证据**：✅ 读码。`task.status="done"` 后仍在 `try` 内 `await bus.publish("task.completed")`；CancelledError 分支无条件改为 skipped。
- **位置**：`mvp/app/orchestrator.py:1740-1755`、`1770-1778`
- **后果**：取消恰好落在 publishing 窗口时，已完成结果从汇总里消失，`_finish` 判“存在未完成任务”。
- **修法**：CancelledError 分支先判 `if task.status in ("done","failed"): raise`，不覆盖终态。

### RUN-05 `_execute` 置 running 与进入 try 之间有 await，取消落地会留下永久 running 任务

- **证据**：✅ 读码。
- **位置**：`mvp/app/orchestrator.py:1699-1712`
- **后果**：`task.status="running"` 后、`try` 前的 `await bus.publish("task.started")` 被取消，异常在 try 之外，CancelledError 处理不执行；DB 留下 running 任务，`_mark_pending_skipped` 又不覆盖它。
- **修法**：把 started 事件与状态更新挪进 try，或在最外层 `except BaseException` 统一回收。

### RUN-07 `estimate_tokens` 对中文低估约 3 倍，压缩阈值失效并触发不可重试的 400

- **证据**：✅ 读码。`len(text) // 3`，中文约 1 字符 1 token。
- **位置**：`mvp/app/llm.py:34-39`、`mvp/app/orchestrator.py:2164`
- **后果**：`CONTEXT_COMPACT_TOKENS=40000` 实际对应 8–12 万真实 token；压缩迟迟不触发，长中文任务最终因上下文超限 400 失败，重试第二个模型同样失败。
- **修法**：CJK 按 ~1 token/字、ASCII 按 ~1/4 估算；或直接用 provider 返回的 `prompt_tokens` 作为下一轮依据。

### UI-01 Enter 键绕过 `submitBtn.disabled`，可重复创建运行/重复发对话

- **证据**：✅ 读码。`submit()` 没有在途标记，`state.runId` 在 POST 返回后才赋值。
- **位置**：`mvp/static/index.html:4694-4722`、`5113-5119`

- **后果**：`POST /api/runs` 两次，产生两个并行完整运行（真实计费）；对话模式重复发送同一条消息。

### UI-02 `selectRun` 竞态：快速切换会挂错 SSE，并把旧运行事件渲染进当前运行

- **证据**：✅ 读码。`applyRunData` 有 runId 守卫，但 `selectRun` 在 `await refreshRun()` 之后仍会用旧的 `id` 执行 `toggle("active")` 和 `openStream(id)`；`handleEvent` 没有 runId 守卫。

### UI-03 对话流没有运行作用域：切换运行后旧流继续污染新运行的 `state.messages`

- **证据**：○ 审计读码（`sendChat` / `handleChatEvent` 未校验 run）。
- **位置**：`mvp/static/index.html:1913-1952`、`1954-2026`、`2267-2269`
- **后果**：A 的 `user`/`start`/`done` 帧被 push 进 B 的对话框；`mergeMessages` 会把它当“未落库的本地消息”永久保留，刷新也不消失。

### UI-04 “重跑”始终可见且无保护，运行中点击会并行复制一次运行

- **证据**：✅ 读码。`/rerun` 不检查源运行是否 active；前端无 disabled/确认。
- **位置**：`mvp/static/index.html:1317`、`4840-4850`；`mvp/app/main.py:1314-1350`
- **后果**：运行中连点重跑，每次 `orchestrator.start` 一个新运行，两个全量运行并行烧钱。
- **修法**：非终态时隐藏/禁用重跑；点击后立即 disabled；后端 `/rerun` 对 active 源运行返回 409。

### UI-05 空闲标签页永远不再刷新运行列表，也轮询不到其他设备发起的审批

- **证据**：✅ 读码。`activeRuns` 只在 `loadRuns` 里更新（`index.html:1537`），而 `loadRuns` 又被 `activeRuns > 0` 门控（`5356-5358`），形成死锁。
- **位置**：`mvp/static/index.html:5351-5360`、`4365-4370`、`1537`

## 已核查、未发现问题的方向

- **中间件路径匹配**：大小写、尾斜杠、`//`、`%2F`/`%2e`、`/api` 前缀外白名单——未发现可利用绕过；公开路径是精确集合匹配。唯一小瑕疵：`POST /api/auth/login/` 会先 401 而不是 307，前端不用该形态。
- **会话过期比较**：`created_at`/`last_seen` 与 `time.time()` 都是 epoch 浮点，无时区/字符串比较问题；`touch_session` 60 秒节流正确。
- **设备 token**：只存 sha256，用索引查找；`mask_key` 不泄漏明文；`attach` 对旧连接 `cancel_all` 并 close；`detach` 用 websocket 身份防误删。
- **审批 future 竞态**：`resolve` 与 `cancel_run` 都有 `future.done()` 守卫，单事件循环内不会在已取消的 future 上 `set_result`；超时由 `finally` 清理。
- **路径沙箱本体**：`_path_within`/`commonpath`、盘符大小写、UNC、8.3 短名、`..` 混分隔符、尾点空格都被 `resolve()` 归一；未发现越界写（仅剩 SEC-09 的枚举越界）。
- **前端 XSS**：所有后端字符串进 `innerHTML` 的位置都经 `esc()`；模型/工具输出只进 `textContent`；登录 token 不落 localStorage。
- **调度依赖解析**：过滤前向/自引用，环不可能出现；单任务失败会 skipped 下游；`MAX_CONCURRENCY` 计数在所有路径成对（除 RUN-01 的双调度器会翻倍）。
- **上下文压缩的 tool 配对**：`_context_messages` 的 tail 起点会回退跳过孤立 `tool` 消息，调用点都在完整工具批次之后；未发现压缩本身切断配对（问题只在 token 估算）。
- **前端语法**：抽取内联 `<script>` 跑 `node --check` 通过；218 个 id 无重复，214 个 `$("...")` 引用全部存在。
